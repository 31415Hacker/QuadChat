QuadChat Privacy Policy

Last updated: September 9, 2026

QuadChat is a small private group chat application created and operated by a single developer. This page explains what data we collect and how it is used.

What data we collect

  • Account data: We use Firebase Authentication to manage accounts and password credentials, and store your email address and display name. Google sign-in provides account information such as your email address, name, and profile picture; QuadChat does not receive your Google password.
  • Signup requests: When you request access, we store your email address, display name, sign-in provider, request status, and submission time. Review records include the reviewing admin's user ID and review time. Password-based requests also store your chosen password as described below.
  • Invites and approvals: We store invite codes, optional email restrictions, the creating admin's user ID, creation time, and whether a code was used. Redemption records include the email address that used the code and when. Approval records are associated with your email address and may include your name, provider, approving admin, and approval source.
  • Profile data: You may optionally upload a profile picture, which is stored on Cloudinary.
  • Messages: Messages and files you send in channels are stored in Firebase Firestore and Firebase Realtime Database so other signed-in users can see them.
  • Presence: While you are signed in, we record that you are online using Firebase Realtime Database. This is removed when you sign out.
  • Notifications: Browser notifications are sent locally on your device. We do not run a push notification server.

How we use your data

Data is used to operate the chat application: reviewing access requests, validating invite codes, recording approvals, creating accounts, preventing abuse, showing messages to other users, displaying your profile, and showing online status. We do not sell or share your data with third parties for advertising or marketing.

Signup request passwords and admin access

For a password-based access request, the current implementation stores your chosen password in readable form in the Firestore request record so an admin can approve creation of your account. This is separate from Firebase Authentication's password storage. Authorized admins can read the complete request record, including this password, even though the admin interface does not display it. Do not reuse a password from another service for an access request.

Admins can read signup requests and invite-code records to manage access. Signed-in users can read only the approval record for their own email address through the client. Direct password signup with an invite code does not create a password-bearing request record.

Retention of signup records

Rejecting a request deletes its request record. Approval currently retains the request record, including its password for password-based requests. There is no automatic expiration for these records. Used invite codes remain stored until revoked, and approval records remain stored. Deleting your account does not automatically delete signup requests, approval records, or invite-code redemption records. Contact the operator below to request removal of these retained records.

Third-party services

  • Firebase Authentication handles sign-in and account credentials. Passwords submitted with access requests are also stored separately in Firestore as explained above.
  • Firebase Firestore and Realtime Database store messages, profiles, presence, and signup-management records.
  • Cloudinary stores uploaded files and profile pictures.
  • Cloudflare Turnstile provides CAPTCHA for password signup and access requests. The browser interacts with Cloudflare for verification, and our server sends the CAPTCHA response token to Cloudflare to validate it.
  • Vercel hosts the application and server endpoints that process signup requests, approvals, and invite codes.

These providers have their own privacy practices.

Your choices

  • You can remove your account at any time from the Settings panel. This deletes your profile data and authentication account, but not the retained signup records described above.
  • Messages you have sent may remain visible to other users unless an admin removes them.
  • You can clear browser data to remove local state.
